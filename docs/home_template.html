Small model, explicit behavior

use rullst_orm::FromRow;

#[derive(Clone, Debug, FromRow, rullst_orm::Orm)]
#[orm(table = "users")]
struct User {
    id: i32,
    email: String,
    #[orm(encrypted)]
    recovery_note: Option<String>,
}

let user = User::find(42).await?;

Generated persistence encrypts annotated values before SQL and decrypts loaded models before fetch hooks. Randomized encrypted columns deliberately reject filtering and sorting; raw SQL remains caller-owned.

Choose by architecture, not scorecards

Project Best fit Relationship to Rullst
Axum Focused HTTP routing and Tower composition Rullst builds on it and should preserve direct access to it.
Actix Web Mature, focused Rust web services An established alternative when an integrated suite is unnecessary.
Loco Rails-inspired Axum applications The closest batteries-included Rust comparison and a DX reference.
Leptos / Dioxus Reactive Rust UI and full-stack rendering Frontend-first choices; Rullst defaults to server-rendered HTML/HTMX.

Ecosystems change. This compact positioning guide links to each project's own documentation and avoids claims that another framework “does not have” a feature.

What still blocks v12

  • All local gates and Linux/macOS/Windows CI must be green on one immutable candidate SHA.
  • Exact packages and a crates.io-only consumer must reproduce from the candidate artifacts.
  • Security advisories require resolution or a narrow, owned and expiring exception.
  • External review, an operated release candidate and human GO/NO-GO approval cannot be replaced by local tests.
