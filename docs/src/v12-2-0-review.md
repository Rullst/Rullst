# Rullst 12.2.0 release review

Scope and release requirements, prepared on 2 October 2026. The supported
stable line is `v12`; `main` develops v13. Source preparation and publication
are separate operations. Consult the [release record](v12.md) and the registry
for publication evidence.

## Scope and compatibility

12.2.0 builds on published 12.1.2 source
`89332c3cd12ee32561bb52c7703d1e37b9475026`. It ports the fixes found by the
v13 review of every framework crate and of the CLI generators and starters.
The [changelog](https://github.com/Rullst/Rullst/blob/v12/CHANGELOG.md) lists
each fix; the [upgrade notes](migration-v12-1.md#upgrading-to-122) and the
[ORM checklist](crates/orm.md#upgrading-from-121) list what an existing
application can notice.

The release is a minor version because the ports add defaulted trait methods,
accessors, constants, hidden ORM helpers and two internal features of
`rullst-orm-macros` (`runtime-feature-gates` and `redis`, enabled by the
matching `rullst-orm`). No public API is removed or changed, the SemVer check
against the published 12.1.2 packages passes, and every manifest keeps Rust
**1.96.0**. External dependency requirements are unchanged except `idna`,
which `rullst-mail` now names directly (it was already in the graph through
`url`), `sqlx-core` 0.9.0, which `rullst-orm` names for its savepoint handling
(the version `sqlx` 0.9.0 pins), and the `span-locations` feature of
`proc-macro2` in the CLI.

Behaviour that existing applications can notice includes:

- the ORM's nested transactions, `SecretString` serialization, `paginate()`
  limits, Redis model hash and query-cache keys, and new typed errors;
- queue lease fencing and the failure of a job whose fifth lease stalls;
- HTMX validation responses with `200 OK` and `X-Rullst-Validation-Status`;
- IPv6 rate-limit keys per /64, honeypot, redaction and DLP changes;
- mail recipient, link and attachment checks;
- Capital Wise, Paddle and Razorpay webhook handling and new MySQL quota keys;
- generators that refuse to overwrite files, `make:mfa`, Foundry service
  accounts, and fixed starter seeds and indexes.

Applications generated by 12.1 keep building. Generated files are copied code:
apply a starter fix by reviewing its diff against a newly generated project.

## Required admission before a release decision

1. Review the complete diff from the published 12.1.2 tag. Verify all
   sixteen package versions and internal requirements, the workspace and ten
   fuzz lockfiles and the packaged README links.
2. Reach **28/28** in the source-bound admission verifier for the exact final
   `v12` SHA: every push workflow plus the manual `ci.yml`, DAST, fuzzing,
   Kani, Miri, Omni, property and sanitizer runs listed in
   `.github/release-required-workflows.json`.
3. Provide fuzz evidence for all 40 targets. Reuse only eligible, unexpired,
   input-equivalent campaigns under the existing equivalence policy; the ports
   change most fuzzed crates, so expect fresh campaigns.
4. Let the release workflow validate archives for all sixteen packages,
   archive-only consumers, the installed CLI and its blueprints, and the four
   native CLI builds, and attest them before the protected publication step.
5. Obtain the separate publication decision. This preparation does not
   authorize a tag, a crates.io publication or a security advisory.

## Application action and boundaries

After publication, update the Rullst dependencies and lockfile, read the
upgrade notes, rebuild and redeploy. Updating dependencies does not rewrite
generated files, migrate data in Redis or rotate secrets. Tenant-scoped Redis
model hashes written by 12.1 need the one-time procedure in the
[ORM notes](crates/orm.md#upgrading-from-121). PostgreSQL projects generated by
12.1 whose seeded tables reject the first insert need the sequence fix in the
upgrade notes. Portfolio pages generated before this release must apply the
escaping fix by hand.
