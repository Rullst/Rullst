Rullst **12.0.0** was published on September 15, 2026. This page is the concise
record of that release; it is no longer a development backlog or launch
checklist.

## What v12 stabilizes

Version 12 stabilizes the **bounded public contracts** described by the
[Single Source of Truth](spec.md). Major delivered areas include the Axum/Tokio
runtime and CLI scaffolding, relational ORM foundations, typed Turso support,
bounded optional persistence adapters, authentication and security controls,
provider-oriented AI, payments and mail, broker-neutral local messaging,
Studio and Nexus, and bounded Omni packaging foundations.

“Stable” means the documented v12 APIs and stated boundaries are suitable for
normal SemVer maintenance. It does not mean that every roadmap idea is complete
or that every third-party service, deployment, mobile device, fiscal authority,
or hardware platform has been homologated.

Use these active sources instead of old development percentages:

- [Specification](spec.md) — normative architecture and capability boundaries;
- [Capability status](capability-status.md) — compact implemented/partial/
  roadmap view;
- [Capability ledger](capability-ledger.md) — detailed evidence and limitations;
- [Release audit](v12-release-audit.md) — repository-owned verification record;
- [Changelog](https://github.com/Rullst/Rullst/blob/main/CHANGELOG.md) — exact
  user-facing changes;
- [Workflow guide](https://github.com/Rullst/Rullst/blob/main/WORKFLOWS.md) —
  current automated, scheduled, and manual checks.

## Verification summary

The stable candidate passed the required exact-SHA hosted gates and the tag-only
publication pipeline. The maintained assurance system covers multi-platform
tests, strict linting and formatting, package consumers, documentation,
coverage floors, dependency and source policy, code scanning, generated
applications, DAST, property tests, sanitizers, Miri, Kani, fuzzing, Omni
compile matrices, and release artifact reproduction.

Every result is scoped to its workflow, target inventory, toolchain, commit,
fixtures, and environment. For example, compilation of an unsigned mobile shell
does not prove physical-device behavior or app-store acceptance, and protocol
fixtures do not prove acceptance by a live provider. The
[release audit](v12-release-audit.md) records those evidence boundaries.

## Upgrading to v12

Existing applications should follow the [v12 migration hub](migration-v12.md)
and the guide for their starting line:

- [v5 to v12](migration-v5-to-v12.md);
- [v6 to v12](migration-v6-to-v12.md);
- [v11-era dependencies to v12](migration-v11-to-v12.md).

`cargo rullst upgrade --dry-run` and `cargo rullst upgrade` provide an
assisted, inspectable migration workflow. They do not silently rewrite arbitrary
application semantics; review the generated plan, back up application data,
commit a clean baseline, run migrations in a safe environment, and execute the
application's own tests.

## Maintenance after release

The `12.x` line accepts compatible correctness, security, documentation, and
dependency-maintenance releases. Breaking APIs and substantial new capabilities
belong to v13. Security reports should follow
[`SECURITY.md`](https://github.com/Rullst/Rullst/blob/main/SECURITY.md).
