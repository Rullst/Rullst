# Rullst 12.3.0 release review

Scope and release requirements, prepared on 8 October 2026. The supported
stable line is `v12`; `main` develops v13. Source preparation and publication
are separate operations. Consult the [release record](v12.md) and the registry
for publication evidence.

## Scope and compatibility

12.3.0 builds on published 12.2.0 source
`565e222a3249f788a0eb560b7ecd6a2ce379ad47`. The
[changelog](https://github.com/Rullst/Rullst/blob/v12/CHANGELOG.md) lists each
change and the [upgrade notes](migration-v12-1.md#upgrading-to-123) list what
an existing application can notice:

- `#[deprecated(since = "12.3.0")]` on the Capital and Mail APIs that 13.0
  removes, a runtime warning for deprecated mail transports chosen by
  configuration, and notices from `make:billing` and `make:mail-invoice`;
- `pkcs1 = "=0.8.0-rc.4"` under the Capital `nfse` feature, so fresh
  resolutions compile again;
- Core WAF and Security RASP signatures that refuse injection structure
  instead of ordinary words;
- `cargo rullst audit` and `audit --sbom` using the workspace lockfile from a
  workspace member;
- the hickory 0.26.3 family for three advisories (lockfile only);
- Rust 1.99.0 for the repository toolchain and the generated Dockerfile.

The release is a minor version because it adds deprecations. No public API is
removed or changed and every manifest keeps Rust **1.96.0**. External
requirement changes are the optional `pkcs1` pin, already in the `nfse` graph
through `sad-rsa`, and the exact pins `sea-orm` `=2.0.4` (from `=2.0.3`) and
`xml-sec` `=0.1.17` (from `=0.1.16`). No stored data or generated file changes
on upgrade.

The changes were integrated through
[#414](https://github.com/Rullst/Rullst/pull/414),
[#415](https://github.com/Rullst/Rullst/pull/415),
[#418](https://github.com/Rullst/Rullst/pull/418),
[#424](https://github.com/Rullst/Rullst/pull/424) and
[#427](https://github.com/Rullst/Rullst/pull/427) on `v12`, and
[#438](https://github.com/Rullst/Rullst/pull/438), which also carries this
version preparation.

## Upgrade rehearsal: 12.2.0 to 12.3.0

Run on 8 October 2026 against this candidate, with Rust 1.99.0 on Linux.
The projects were generated by the published 12.2.0 native CLI
(`cargo-rullst-12.2.0-x86_64-unknown-linux-gnu`, whose SHA-256 matched the
release checksums) and were not committed:

```bash
cargo rullst new blank_app --default --blueprint blank --database sqlite --skip-initial-migration
cargo rullst new saas_app --default --blueprint saas --database sqlite --skip-initial-migration
```

Each generated manifest keeps its `version = "12.2.0"` requirements, which
12.3.0 satisfies. A `[patch.crates-io]` table pointed all fifteen library
crates at the candidate's paths, and each lockfile was seeded from the
candidate's `Cargo.lock` and resolved offline. The host-local
`.cargo/config.toml` (linker flags only) was set aside so the shared build
cache could be reused, and `CARGO_PROFILE_DEV_DEBUG=0` bounded memory. Each
project then ran `cargo build --offline` and
`cargo test --offline -- --test-threads=2`.

| Starter | `cargo build` | `cargo test` | Warnings in application code |
|---|---|---|---|
| Blank, SQLite | passed | passed; the starter has no tests (0 run) | none |
| SaaS, SQLite | passed | passed; the starter has no tests (0 run) | 7 `deprecated` |

The seven SaaS warnings are all in the generated
`src/controllers/billing_controller.rs`, and each ends with `removed in Rullst
13.0; see the v13 migration guide row "Capital providers and NFS-e removed"`:

| Line:column | Deprecated item |
|---|---|
| 5:40 | struct `LemonSqueezyProvider`, in the `use rullst::capital::{…}` import |
| 138:53 | struct `LemonSqueezyProvider`, return type of `lemon_provider` |
| 139:20 | struct `LemonSqueezyProvider`, in `lemon_provider` |
| 139:42 | associated function `LemonSqueezyProvider::new`, in `lemon_provider` |
| 141:36 | method `LemonSqueezyProvider::with_store_id`, in `lemon_provider` |
| 310:13 | struct `LemonSqueezyProvider`, in the `"lemonsqueezy"` arm of `portal_redirect` |
| 310:35 | associated function `LemonSqueezyProvider::new`, in the same arm |

Code generated by 12.2 has no `#[allow(deprecated)]`, so these are the
warnings an upgraded 12.2 SaaS project sees. With denied warnings:

- `cargo rustc --offline --bin saas_app -- -D warnings` fails with the same
  seven diagnostics as errors;
- `cargo rustc --offline --bin saas_app -- -D warnings -A deprecated` passes;
- applying the 12.3.0 change to `billing_controller.rs.template` (an
  `#[allow(deprecated)]` on the import, on `lemon_provider` and on the portal
  arm) to the 12.2-generated file makes `-D warnings` pass, so the allows that
  12.3 generators add cover every deprecated use in the generated controller.

Not covered: the starters have no tests, so `cargo test` proves test-profile
compilation only; the applications were not started; Clippy, PostgreSQL and
MySQL projects and `make:mail-invoice` with NFS-e were not rehearsed.

## Required admission before a release decision

1. Review the complete diff from the published 12.2.0 tag. Verify all
   sixteen package versions and internal requirements, the workspace and ten
   fuzz lockfiles and the packaged README links.
2. Reach **28/28** in the source-bound admission verifier for the exact final
   `v12` SHA: every push workflow plus the manual `ci.yml`, DAST, fuzzing,
   Kani, Miri, Omni, property and sanitizer runs listed in
   `.github/release-required-workflows.json`.
3. Provide fuzz evidence for all 40 targets. Reuse only eligible, unexpired,
   input-equivalent campaigns under the existing equivalence policy; Core,
   Security, Capital and Mail changed, so expect fresh campaigns for their
   targets.
4. Let the release workflow validate archives for all sixteen packages,
   archive-only consumers, the installed CLI and its blueprints, and the four
   native CLI builds, and attest them before the protected publication step.
5. Obtain the separate publication decision. This preparation does not
   authorize a tag, a crates.io publication or a security advisory.

## Application action and boundaries

After publication, update the Rullst dependencies and lockfile, read the
upgrade notes, rebuild and redeploy. Code that names a deprecated item keeps
working but warns; a build that denies warnings needs a scoped
`#[allow(deprecated)]` or `-A deprecated` until it moves to the replacement
named in the v13 migration guide. Updating dependencies does not rewrite
generated files.
