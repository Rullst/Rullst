# Preparing an application for v13

**The current source is `13.0.0-alpha.4`, a prerelease, not a stable v13
release.** The first prerelease, `13.0.0-alpha.1`, was published on October 11, 2026.
The 12.x line, on the frozen `v12` branch, reached end of life on 16 October
2026 with 12.3.0 as its last release; `main` develops v13. The development packages use the same v13
version and internal requirements. `rullst-privacy`, `rullst-supervision`,
`rullst-media` and `rullst-labs` join the candidate package inventory and were
first published in 13.0.0-alpha.1. Privacy
has explicit `privacy-*` umbrella features; Supervision, Media and Labs remain
standalone opt-ins.
All packages are published together as each v13 prerelease (twenty-one since
13.0.0-alpha.4 adds `cargo-rullst-extras`); the current one is
`13.0.0-alpha.4`. Cargo never selects
a prerelease on its own, so `cargo add rullst` still selects the end-of-life
12.3.0: opt in with
an exact requirement such as `rullst = "=13.0.0-alpha.4"`. A plain
`"13.0.0-alpha.4"` is a caret requirement that also accepts later alphas, which
may break the API. From 13.0.0-alpha.2 the CLI writes the `=` form; a project
generated by the 13.0.0-alpha.1 CLI has the caret form, so add the `=` to its
`rullst` and `rullst-orm` lines. A
hand-written manifest should also turn off the default features, which compile
the SQLite, PostgreSQL and MySQL drivers, and select the database profile it
uses, as `cargo rullst new` does:

```toml
rullst = { version = "=13.0.0-alpha.4", default-features = false, features = ["strict-postgres"] }
```

Do not request v13 artifacts from
the stable updater before those artifacts have actually been published.

This inventory covers the `13.0.0-alpha.4` development source. Revisit it as the remaining
[delivery priorities](v13-delivery-plan.md) land. It does not promise that every
existing application, provider account or deployment works without review.

To find the rows that affect an application, run `cargo rullst upgrade --dry-run`
with the v13 CLI: its `rullst-upgrade-rules-v4` catalog reports `MUST-CHANGE`
and `REVIEW` findings at `file:line`, each naming the first-column title of its
row below, and `cargo rullst ai upgrade` proposes reviewed fixes for them. The
[assisted upgrade tutorial](tutorials/36-assisted-framework-upgrades.md#v12-to-v13-source-findings)
describes the workflow and [classifies every row](tutorials/36-assisted-framework-upgrades.md#v12--v13-rule-classification).
Rows without rules still need a reading. An application already on a 13.0
prerelease gets only the rules introduced after its version, and the plan says
how many earlier rules it skipped; `--all-rules` applies every rule
([rules by release](tutorials/36-assisted-framework-upgrades.md#rules-by-release)).
An application that already runs 13.0.0-alpha.2 follows the shorter
[alpha.2 to alpha.3 checklist](#upgrading-an-alpha2-application-to-alpha3).

## Changes from the published 12.1.0 source

| Area | Application impact |
| :--- | :--- |
| Existing runtime APIs | Source preparation changes supported dependency requirements; it invents no Rust rewrites. Review the explicit account-session schema migration below even when existing Rust calls still compile. |
| Account/session registry | Before serving requests with the new Auth recovery store, explicitly run `SqlRecoveryStore::migrate()` to add session details and the expiry index. Existing opaque sessions remain valid with unknown historical metadata. Configure expired-session maintenance and authorize new inventory/logout routes; see [session management](session-management.md). The CLI manifest updater does not apply this SQL migration. |
| Private object storage | The optional `storage-s3` candidate requires explicit signing credentials and production validation. Existing cloud constructors stay unconfigured; no bucket, IAM policy or credentials are inferred. See [private storage](private-object-storage.md). |
| R2 public URLs | `Storage::r2(...).url(key)` (and `TenantStorage::url` over R2) now returns `StorageError::Unsupported` instead of `https://<account>.r2.cloudflarestorage.com/<bucket>/<key>`. That S3 API endpoint requires a signature for every request, so the URL never loaded in a browser. Build public URLs from your `r2.dev` or custom domain in the application, or use a signed download with `storage-s3`. |
| Tenant local storage | `TenantStorage` reads, metadata and deletes on local storage return `StorageError::Io` when the tenant directory lies below a regular file (for example a file named `tenants` in the base path), on every platform. On Windows, 12.x and 13.0.0-alpha.1 returned `NotFound` there, as if the object were missing. |
| Recoverable Live UI | Existing `LiveComponent` and `make:live` output keep their original protocol. Opt in to `live::recovery` with explicit authenticated scope, periodic authorization, persistent revisions and atomic domain updates; mount its separate browser module. Full snapshots replace child DOM and never replay uncertain actions. See [Live recovery](live-recovery.md). |
| Distributed tracing | Opt in to `telemetry::distributed` with approved operation names, upstream trust, a collector and owned flush/shutdown. The legacy initializer now uses compatible threaded OTLP/HTTP export and defaults to `127.0.0.1:4318/v1/traces`; `OTEL_EXPORTER_OTLP_ENDPOINT` is a base URL, while `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is exact. Redirects and request bodies over 1 MiB are unsupported; the legacy initializer exports at most 64 spans per request (unless `OTEL_BSP_MAX_EXPORT_BATCH_SIZE` is set), honours `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` and reports dropped batches on stderr, while the minimized profile ignores proxy variables. Review existing collector environment configuration; [the tracing guide](distributed-tracing.md) distinguishes both metadata policies. |
| Core queue | SQLite claims jobs in due-time order, so a due scheduled or handed-back job no longer waits behind later immediate jobs, and `retry_failed_job` keeps the attempt counter (it fences claims) instead of resetting it to 0. A job no worker has a handler for is failed with `HandlerNotFound` at its 720th claim attempt instead of being handed back forever. `dispatch`/`dispatch_at` reject empty names and names over 256 bytes, and `Worker::run` rejects `job_timeout(Duration::ZERO)`, all with `QueueError::InvalidConfiguration`. Redis queue commands wait up to 10 s for a reply instead of 500 ms. Stalled recovery of a claim made without a lease (SQLite `pop`) may now happen up to two seconds after `stalled_after`, never before. Failed jobs that a 12.x process records in a Redis queue, including 12.x workers during a rolling upgrade, are not in the new failed-job index: they are neither counted nor evicted by the 10,000-entry retention, so retry them with `retry_failed_job` or remove them with `purge_failed_jobs` once every worker runs 13. |
| Core scheduler, cache and realtime | `Scheduler::start` returns the new `SchedulerError::InvalidConfiguration` for a zero task timeout; exhaustive matches in other crates are unaffected because the enum is `#[non_exhaustive]`. The Redis cache treats a zero TTL as an already-expired value (the key is removed) and a TTL beyond Redis's expiry range as no expiry, as the memory driver does. `PresenceTracker` counts connections: call `user_left` once per `user_joined`, since a user stays online until the last leave. `Channel::new` clamps the capacity to 65,536. The Traffic Shield database probe gives up at `max_db_latency` and records at least that latency. A Live recovery session no longer counts its own callback and send time as peer silence. `TenantCache` now writes `%` as `%25` and `:` as `%3A` in the tenant segment of its keys (`tenants:a%3Ab:<key>`), so entries of tenant IDs containing those characters start cold, and while 12.x and 13 instances share the cache a `forget` on one version does not remove the other's entry for such a tenant; rely on TTLs or finish the rollout before depending on invalidation. |
| Core memory cache sweeps | `Cache::memory()` sweeps expired entries after a number of operations equal to a quarter of the entries the previous sweep kept (at least 256), instead of every 256 operations, so the sweep cost per request no longer grows with the cache. Reads still never return an expired value; unread expired entries may stay in memory longer in a large cache. |
| Studio queue monitor | Studio lists queue records with the new `QueueDriver::list_job_previews` (at most 2 KiB of each payload and error) instead of `list_all_jobs`. Custom drivers keep working through the default projection of `list_all_jobs`; override `list_job_previews` to cut values in the store. |
| Studio API playground | `Studio::with_openapi` now takes a utoipa 6 `OpenApi`. Applications that build their document with utoipa 5 must upgrade to utoipa 6 (and `utoipa-axum` 0.3 when they use its router helpers). Studio no longer embeds Swagger UI (its `utoipa-swagger-ui` build dependency needs a `zip` release that crates.io has yanked): `/studio/api` is now a server-rendered, read-only reference of the operations, `/studio/api/` redirects to it and `/studio/api/openapi.json` still serves the document. There is no in-page "Try it out"; send requests with an external client. |
| Studio local access and table view | `LocalStudioAccess::loopback_only()` now accepts an IPv4-mapped loopback peer (`::ffff:127.0.0.1`, reported by a dual-stack `HOST=::` listener) instead of returning 403; other mapped addresses stay rejected. The table view, and the public `get_any_value_as_string`, now report a present value that no text, integer, float or Boolean codec decodes (for example a non-UTF-8 BLOB) as `unreadable` instead of `NULL`, and a stored text `NULL` is no longer styled as SQL NULL. |
| LMS blueprint | `--blueprint lms` now generates a small starter: catalog, modules, lessons, an accessible player, enrollment, owner-bound progress, login and a Nexus admin. The complete Academy scaffold (schools, roles, quizzes, activities, scores, automation, notifications, publication, privacy lifecycle) and `--lms-modules` were removed; existing generated applications keep their code. Registration no longer generates the school-membership hook, and the learner dashboard no longer claims a default demo school: it points to the course catalog. Since 13.0.0-alpha.4 this starter is the `examples/lms` application instead (see "CLI starters moved to the examples"). |
| Consumer generators | `make:supervision` was removed with the complete Academy LMS it targeted; integrate `rullst-supervision` directly. `make:privacy` and `make:age-gate` now target only the SaaS starter (`--blueprint saas`, which requires `--tenant-ref`). |
| `html!` event handlers | A dynamic value in an `on*`, `hx-on` or `hx-on-*` attribute (for example `onclick={handler}`) no longer compiles, because escaping cannot make data safe inside JavaScript. Static handler strings still compile; move data-driven handlers into a nonce'd script with `addEventListener` and pass values through `data-*` attributes. The default CSP already blocked such inline handlers. |
| `html!` returns `Markup` | Since 13.0.0-alpha.2, `html!` returns `rullst::html::Markup` (escaped HTML) instead of `String`. Interpolating a `Markup` inserts it as HTML, so a fragment built by another `html!` call is no longer shown as escaped text and needs no `RawHtml`; `String`, `&str` and numbers are still escaped. A function declared `-> String` that returns `html!` no longer compiles: declare it `-> Markup`. `RawHtml(html! { .. })` no longer compiles: interpolate the `Markup` directly. Collect lists with `.collect::<Markup>()` (collecting `Markup` into a `String` does not compile) and use `Option<Markup>` for optional parts. `render_page`/`render_page_with_lang` take `impl Into<Markup>` (wrap a `String` of trusted HTML with `Markup::from_trusted`), and `Live::mount` and native `#[island]` functions return `Markup`. A handler can return `Markup` (`text/html; charset=utf-8`), `Html(html! { .. })` still compiles, `Markup` compares with and reads like a `&str`, and `.into_string()` returns the `String`. See [`html!` returns `Markup`](#html-returns-markup). |
| Core request validation | `ValidatedForm`/`ValidatedJson` return 413 for oversized bodies and 415 for a wrong content type (HTMX requests receive the same code in `X-Rullst-Validation-Status`); other read failures stay 400. Nested errors are keyed `address.zip` and `items[0].name`, and `ValidationError` formatting no longer includes submitted values. Update clients or tests that expected 400 for these cases. |
| Core feature flags and scheduler | A user outside a declared A/B split now resolves to `"disabled"` instead of falling through to the next driver, and a negative database `rollout_percentage` means 0%. `Scheduler::task` uses POSIX weekday numbering (0 and 7 are Sunday) with the day-of-month OR day-of-week rule in UTC; review numeric weekdays in existing schedules. `RullstConfig::environment()` now reports the environment the Server enforces, including a value read from `.env`. Percentage rollouts and A/B variants of the Env, TOML, Memory and DB drivers use a versioned SHA-256 bucket hash instead of `std`'s `DefaultHasher`, so upgrading reassigns users to buckets once (percentages and variant weights are kept). End experiments whose assignment must not change before upgrading, and keep the period in which 12.x and 13 replicas both serve short, because they assign the same user differently. |
| Memory feature-flag splits | A `MemoryFeatureDriver::override_variants` flag (including `FeatureManager::overrides()`) no longer reports `enabled`/`enabled_for` as true for everyone. Like the Env, TOML and DB drivers, `enabled_for` is true only for identifiers assigned a variant named `"enabled"`; like the Env and TOML drivers, `enabled` is false. Gate A/B code on `variant`. |
| Database feature-flag splits | A `rullst_feature_flags` row whose `variants` column holds an A/B split now makes `DbFeatureDriver::enabled` (and therefore `feature::enabled` when the DB driver answers) false, as in the Env, TOML and Memory drivers. It was true when `rollout_percentage` was empty. `enabled_for` and `variant` are unchanged; gate A/B code on `variant`. |
| Security headers | Core and both Security header layers preserve an endpoint's exact `Referrer-Policy: no-referrer`, including when it occurs among duplicate values. Other endpoint values still yield to `SecureHeadersLayer` and `CspSecurityLayer`; the Core baseline now keeps them (see Core security header precedence). Review handlers that intentionally set this more restrictive policy. |
| Core WAF signatures | `waf_middleware`, which `Server` mounts in staging and production, now refuses injection structure instead of SQL and shell keywords. Ordinary text such as "Please select an option", "Delete my account" or "curl the API with your token" in a query, `Referer`, cookie or body is no longer rejected with 403. A quote followed by `or`/`and` and a comparison or by a SQL comment, a `;` followed by a SQL statement, `union [all] select`, SQL probe functions (`sleep(`, `waitfor delay`, `information_schema`…) and a shell metacharacter (`;`, `\|`, `&&`, a backtick, `$(`) followed by a command name are still refused, also when `/* */` comments separate keywords; XSS and traversal signatures are unchanged. JSON bodies are inspected key by key and string by string after decoding, so a `\u003c` escape no longer hides `<script` and JSON quotes no longer join a signature. The WAF remains a coarse baseline: keep parameterized SQL and shell-free process APIs. |
| Core security header precedence | `headers_middleware` (the staging and production baseline in `Server`) now adds each security header only when the response has none, so an explicit value from a handler or an inner layer (`Content-Security-Policy`, `X-Frame-Options`, HSTS, `Referrer-Policy`, `Permissions-Policy`, COOP, CORP, COEP, `X-XSS-Protection`) wins over the baseline instead of being replaced. When `rullst_security::SecureHeadersLayer` ran inside it, which now marks its responses with the new `rullst::security::SecurityHeadersApplied` extension, the baseline leaves all of those headers alone, so the headers its `SecureHeadersConfig` omits (`None`) stay absent. `Cache-Control: no-store` for responses without a cache policy and the shared `CspNonce` are unchanged. Review handlers and layers that set a weaker value (for example `Referrer-Policy: unsafe-url` or a CSP with `'unsafe-inline'`) and relied on the baseline to replace it. |
| AI provider streaming and stop reasons | `AnthropicProvider` and `GeminiProvider` now implement `StreamingAiProvider`, and their `capabilities()` report `streaming: true` and `explicit_cancellation: true`; code that chose a transport from those flags now streams them. Gemini's non-streaming `chat`/`prompt` now fail with `AiError::ApiError` when the candidate's `finishReason` is `MAX_TOKENS` or a safety-class reason (`SAFETY`, `RECITATION`, `LANGUAGE`, `BLOCKLIST`, `PROHIBITED_CONTENT`, `SPII`, `IMAGE_SAFETY`) instead of returning the partial text, matching the Anthropic and OpenAI behaviour; raise the output limit or handle the error. The OpenAI-compatible stream (`OpenAiCompatibleProvider` with `with_streaming()`, used for OpenAI, DeepSeek, local servers and loopback Ollama) likewise fails with `AiError::ApiError` when a chunk reports `finish_reason` `length` or `content_filter` instead of completing with the text received so far. |
| AI image-beacon guardrail | The `data_exfiltration` check inspects every Markdown image even when the text contains no literal `http://` or `https://`: scheme-relative (`//host`), slash-less (`http:host`), backslash and reference-style beacons (with the definition anywhere in the text), unterminated destinations and labels containing a code span, raw HTML or an autolink that could hide a `]` (or a `<` followed by a bracket before the next `>`) are blocked; bracket-free constructs such as `Vec::<u8>` or `Box<dyn Fn()>` inside `vec![...]` no longer make a label ambiguous. It decodes CommonMark backslash escapes and entity or numeric character references in destinations, so `![x](https&#58;//host/c)` is blocked like the literal URL; an unrecognized named reference (for example `&eacute;`) makes that destination untrusted. Images and definitions inside code spans and closed fenced or indented code blocks are ignored, as CommonMark never renders them (code whose extent depends on an ambiguous layout is still read); lines end at LF, CRLF or a bare CR and only spaces and tabs make a line blank, so a bare CR or a no-break-space line can no longer turn a rendered image into apparent indented code. A reference image whose ASCII label matches no definition, such as `vec![x]` or `routes![...]` in Rust code, renders as literal text and is not blocked even next to a remote URL; a non-ASCII label, a label with a backslash-escaped bracket (read with its escapes, as `[a\]b]`) or an unterminated label is still blocked when the text names a remote URL, and a reference image whose definitions are all local is not blocked by an unrelated link. An inline image whose destination and title are not certainly valid (such as `![ß](x y)`) is also judged by the shortcut reference CommonMark falls back to, matched with Unicode case folding. |
| AI RAG tenant tags | `RagPipeline::answer` checks the tenant tag of every document the retriever returns, including those after the context budget is exhausted, and fails with `RagError::InvalidDocument` (audited as `ContextRejected`, no provider call) instead of answering when any of them belongs to another tenant. |
| Anthropic provider output | `AnthropicProvider` requests up to 16,000 output tokens instead of a fixed 1,024, and a reply whose `stop_reason` is `max_tokens`, `model_context_window_exceeded` or `refusal` now fails with `AiError::ApiError` instead of returning the partial text as a complete answer (so `StatefulChat` does not store it and `RagPipeline` audits `GenerationFailed`). Choose another limit with the new `with_max_tokens`; a longer reply can take longer than the 30-second default request deadline, so raise it with `with_request_timeout`. |
| OpenAI provider output | `OpenAiProvider` vision requests no longer send `max_tokens: 1024` (deprecated by OpenAI and rejected by reasoning models); like text requests they leave the output limit to the model. A chat, vision, JSON or structured-output reply whose `finish_reason` is `length` or `content_filter` now fails with `AiError::ApiError` instead of returning the partial text. DeepSeek and `OpenAiCompatibleProvider` are unchanged. |
| Ollama host | `OllamaProvider::new` and `AiClient::auto()` read `OLLAMA_HOST` the way Ollama does: a scheme-less value such as `127.0.0.1:11434`, `localhost` or `[::1]` now means `http` with port 11434 unless a valid port is named (`ollama.com` alone means `https://ollama.com:443`), instead of producing a URL every request rejected. Values with `http://` or `https://` are used as before. |
| AI chat memory keys on MySQL/MariaDB | `SqlChatMemory` tenant and conversation IDs compare case-sensitively on every backend; new MySQL/MariaDB tables use `ascii_bin` key columns, and `prepare_schema` never alters an existing table. On a table created by 12.x, an ID that differs from a stored one only by letter case fails closed (`ChatMemoryError::InvalidConfiguration`, `ConversationNotFound` or `RevisionConflict`). Stop chat-memory writers, back up both tables, review conversations that 12.x may have merged and apply the migration in the [AI README](https://github.com/Rullst/Rullst/blob/main/rullst-ai/README.md#upgrading-mysqlmariadb-chat-memory-tables). PostgreSQL and SQLite tables are unchanged. |
| Core CSRF on HEAD | `csrf_middleware` handles `HEAD` like `GET`: it installs the request-scoped `CsrfToken` and, when the request carries no CSRF cookie, sends the same `Set-Cookie` that GET would. A `get` route that extracts `Extension<CsrfToken>` now answers HEAD (monitors, crawlers, `curl -I`) with its GET status instead of 500. |
| Hot-reload machine endpoints | `Server::new_hot(...).with_machine_endpoints(policy)` now authenticates the policy's exact routes in the development hot-reload server, as the static server already did in every environment. Previously hot reload ignored the policy and those routes ran unauthenticated; development machine clients must now send the configured credentials. |
| Core JSON PII masking | With `enable_pii_masking`, JSON string escapes are decoded before masking, so `\uXXXX` hex digits never join a card-number run (which produced invalid JSON such as `\u****`), while escaped digits and `@` are masked like their literal characters. A masked character is written as a literal `*`; unmasked escapes keep their original spelling. |
| Core PII masking of range responses | With `enable_pii_masking`, a `206 Partial Content` response whose range would be masked now becomes `502` with `Cache-Control: no-store` instead of a rewritten 206 that kept its status but lost `Content-Range`. A range that needs no masking passes through unchanged. A `multipart/byteranges` response, previously passed through uninspected, is now checked part by part and withheld the same way when a textual part would be masked or when the body cannot be split exactly (invalid boundary or delimiter line, more than 256 parts, a part header block over 8 KiB, no close delimiter). |
| Security DLP, RASP and honeypot | `DlpResponseLayer` now also masks XML (`application/xml`, `+xml`), YAML and `application/javascript` responses, as it already did for text and JSON; review clients that compare such bodies byte for byte. A `206 Partial Content` response whose range contains a masked secret now becomes `502` with `Cache-Control: no-store` instead of a rewritten 206 without `Content-Range`. A `multipart/byteranges` response, previously passed through uninspected, is now checked part by part and withheld the same way when a textual part contains a secret or when the body cannot be split exactly (at most 256 parts and 8 KiB of headers per part). A honeypot ban TTL beyond the monotonic clock (for example `Duration::MAX` in `HoneypotState::try_with_limits`) now bans until the furthest representable deadline instead of never banning, and telemetry lists a ban only when one was stored. `redact_secrets` no longer increments `dlp_secrets_masked` or emits `DLP_SECRET_LEAK_PREVENTED` events (it counts only `log_redactions`), so dashboards stop reporting log lines as blocked responses. `RaspSecurityLayer` now serves requests whose `User-Agent` carries the stock PowerShell product token (`PowerShell/7.4.1`, `WindowsPowerShell/5.1…`) instead of returning 403; `powershell` elsewhere, or as execution syntax in that header, still blocks. `HoneypotLayer` telemetry (`honeypot_route_hits`, ban reasons and live events) names the configured trap path instead of the request's letter case, so case variants share one route counter. |
| Security audit log lines | `StdoutAuditLogger` writes `actor`, `action` and `resource` as quoted, escaped strings (`actor="bob" action="login"`) instead of raw text, so a value with spaces, `=` or a line break can no longer forge fields or lines. Update log parsers and alerts that match the unquoted 12.x form. |
| Connect generic OIDC | `OidcProvider` no longer rejects an ID token or userinfo response without the optional `name` claim (`Missing name in id_token`/`userinfo`); `ConnectUser::name` falls back to `given_name`/`family_name`, `preferred_username`, `nickname` and may be empty. Applications that relied on a non-empty name must handle the empty case. An ID token without a `kid` header is now verified when the issuer's JWK Set holds exactly one key that fits the token's asymmetric `alg`, instead of failing with `Missing 'kid' header`; other sets still fail closed, and a kid-less symmetric token now reports the algorithm error before any JWKS request. |
| Age assurance | Optional `rullst-privacy` APIs and `make:age-gate` add an authenticated native declaration journey. Existing apps acquire no age policy, verified age, guardian relationship, replay storage or camera capture by upgrading a dependency. |
| Optional consent and export | `make:privacy` adds explicit versioned choices, effective withdrawal of the demonstrated optional greeting and an authenticated own-account name/email export. It requires reviewed application installation and explicit consent-store initialization. It is not a complete export of all application data or automatic worldwide legal compliance. |
| Project context | New projects receive application instructions and a bounded metadata map. `generate:ai-context` replaces recognized legacy source-concatenation output, preserves existing `AGENTS.md`, and adds a non-writing `--check`. See the [context guide](project-context.md) for size/path/configuration limits. |
| Typed API generation | `generate:api` is an explicit additive OpenAPI profile with generated Rust codecs and a TypeScript client. Install/review the schema and application handlers; existing scanning generators and routes are not migrated automatically. See the [supported profile](typed-api.md). |
| CLI generator output | `make:migration:auto` reads `#[orm(table_name = "...")]`, qualified `#[derive(rullst_orm::Orm)]` and a `table` option written after other `#[orm(...)]` options, so it diffs the declared table instead of a guessed `<struct>s` table. `make:live` imports `rullst::async_trait` instead of the undeclared `async_trait` crate; edit components generated earlier the same way. `make:scalar` imports `rullst::web::axum::Router` instead of the undeclared `axum` crate. `eject` writes a template that compiles (Axum through `rullst::web::axum`) and wraps its placeholder routes in the configured security baseline; it still does not carry over application routes, so `--force` output needs the routes moved from `src/main.rs.rullst-backup`. `foundry:deploy` uploads the binary to `/opt/rullst/<app>/incoming/<bin>.upload` (created `0700` for the SSH user during provisioning) instead of `/tmp`, and the remote step requires `stat` and `sha256sum` to check its owner and digest. `foundry:init` creates a missing `.gitignore`, no longer treats a comment or `!Foundry.toml` as protection, and writes `Foundry.toml` with mode `0600`. `make:model` rejects names such as `Match` or `Type` whose module would be a Rust keyword, as `make:resource` already did. `make:migration` keeps leading `m` characters of the name (`modify_users` previously became `odify_users`) and rejects names that are not ASCII letters, digits, `_` or `-`; generators that refresh `src/migrations/mod.rs` now fail on an `m*.rs` file whose name is not a valid module name instead of writing an unparsable registry. `make:controller --api` and `make:resource --api` handlers extract `Json<CreateDto>`/`Json<UpdateDto>` instead of `Form`, so clients must send `application/json`; controllers generated earlier keep `Form` until edited. `generate:ts` also scans `src/lib.rs` and turns `{id}`/`{*path}` captures into URL-encoded method arguments; regenerate `rullst-client.ts`, whose parameterized methods change signature. ### `html!` returns `Markup`

`cargo rullst upgrade` reports `V13-HTML-MARKUP-RETURN` for a function that
declares a `String` (`String`, `Html<String>`, `Result<String, _>`) and
returns `html!`, and `V13-HTML-RAW-MARKUP` for `RawHtml` around `html!`
output. Before:

```rust,ignore
use rullst::html;
use rullst::html::RawHtml;

fn badge(label: &str) -> String {
    html! { <span class="badge">{label}</span> }
}

fn rows(names: &[&str]) -> String {
    let rows: String = names
        .iter()
        .map(|name| html! { <tr><td>{name}</td><td>{RawHtml(badge("new"))}</td></tr> })
        .collect();
    html! { <table>{RawHtml(rows)}</table> }
}
```

After:

```rust
use rullst::html;
use rullst::html::Markup;

fn badge(label: &str) -> Markup {
    html! { <span class="badge">{label}</span> }
}

fn rows(names: &[&str]) -> Markup {
    let rows: Markup = names
        .iter()
        .map(|name| html! { <tr><td>{name}</td><td>{badge("new")}</td></tr> })
        .collect();
    html! { <table>{rows}</table> }
}

assert_eq!(
    rows(&["<Ana>"]),
    "<table><tr><td>&lt;Ana&gt;</td><td><span class=\"badge\">new</span></td></tr></table>"
);
```

Keep `RawHtml` (or `Markup::from_trusted`) only for trusted HTML produced
outside `html!`, such as a sanitizer's output, and never for request data.

## Upgrading an alpha.2 application to alpha.3

This checklist moves an application from 13.0.0-alpha.2 to 13.0.0-alpha.3.
The rows above that name alpha.3, and the ORM database-managed columns, ORM
dirty tracking and Omni rows, are the changes in between. The
[rehearsal on generated starters](tutorials/36-assisted-framework-upgrades.md#1300-alpha2-to-1300-alpha3)
shows the expected result.

1. **Prepare.** Work on a branch with a clean tree and a committed
   `Cargo.lock`, record the current `cargo test` result, and back up every
   database (check that the backup restores).
2. **Install the alpha.3 CLI.**
   `cargo install cargo-rullst --version =13.0.0-alpha.3 --locked --force`,
   then `rullst --version` must print `13.0.0-alpha.3`.
3. **Name the features.** `rullst` (which enabled `orm`, `drivers-all` and
   `queue-sqlite`) and `rullst-orm` (`drivers-all`) have no default features
   any more. A dependency that relied on them lists what the application
   uses, for example
   `rullst = { version = "=13.0.0-alpha.3", default-features = false, features = ["orm", "strict-sqlite", "queue-sqlite"] }`
   (`drivers-all` keeps the three SQLx drivers). Remove `offline-sync` from
   `rullst` and `rullst-core` features. Projects generated by `cargo rullst
   new` already disable the defaults and list their features.
4. **Inspect.** Run `cargo rullst upgrade --dry-run` and fix every
   `MUST-CHANGE` finding first (`V13-OFFLINE-SYNC-REMOVED` is the one alpha.3
   adds). These findings concern alpha.3 changes and usually need an edit:
   - `V13-ORM-SKIP-MANAGED-COLUMNS`: replace `#[orm(skip)]` with
     `#[orm(db_default)]` on `User::is_admin` and `User::session_epoch` (SaaS,
     LMS and `cargo rullst auth` models generated by alpha.2) and on any
     other column the database manages. No schema change is needed.
   - `V13-ORM-TRANSACTION-ERRORS`: `Orm::transaction` returns its closure's
     own error type, so match that error instead of `DatabaseError`. A
     closure whose error type lacks `From<rullst_orm::Error>` (such as
     `String`) no longer compiles, which `cargo check` reports; return
     `rullst_orm::Error` or an application error that wraps it.
   - `V13-RULLST-DEFAULT-FEATURES` and `V13-ORM-DEFAULT-FEATURES`: step 3.
   - `V13-CONNECT-GITHUB-EMAIL`: the GitHub provider now returns the primary
     address and GitHub's verified flag; link or create accounts on it only
     when `email_verified == Some(true)`.
   - `V13-OMNI-REMOVED` and `V13-OFFLINE-SYNC-REMOVED`: replace the Omni
     shell with `cargo rullst make:pwa`, as the Omni row describes.

   The plan reads the application's version from its manifests and
   `Cargo.lock` and applies only the rules introduced after 13.0.0-alpha.2,
   which are the ones above; its `Rules:` line says how many earlier rules it
   skipped. If it names 13.0.0-alpha.1 instead, a requirement still has the
   caret form of the alpha.1 CLI (`"13.0.0-alpha.1"`), and the alpha.2 rules
   are listed too. `--all-rules` also lists the rules for the 12.x to 13
   changes that alpha.2 already contained, such as `V13-REFERRER-NO-REFERRER`,
   `V13-MAIL-FACADE-CONFIG`, `V13-LMS-RECORD-PROGRESS` and
   `V13-HOT-RELOAD-MACHINE-ENDPOINTS`; an alpha.2 application already runs
   with those changes, so they need no edit for this step.
5. **Apply.** `cargo rullst upgrade` pins every Rullst dependency, including
   direct `rullst-auth`, `rullst-security` or `rullst-connect` lines, to
   `=13.0.0-alpha.3`, runs `cargo fix` and `cargo check --locked`, and
   restores the files if a step fails (`--keep-on-failure` keeps the failed
   state for diagnosis). Make the edits from step 4, then update the
   dependencies of the changelog's Dependency security entries that the
   lockfile contains:
   `cargo update -p ammonia -p rustls-webpki -p webpki-roots -p webpki-root-certs`.
6. **Read the alpha.3 rows that no rule locates** and adjust the application
   where it depends on them: ORM transactional migrations and the pool (no
   `Orm::pool()` inside a `within_transaction()` migration), Connect mock
   credentials and Connect mock authorization URL (mock credentials need the
   `mock` feature, `oauth-mock` on the facade), Production log defaults
   (health probes are no longer logged, SQLx INFO events are hidden, and an
   invalid `RULLST_LOG_HEALTH_PROBES` stops startup), and the opt-in ORM
   dirty tracking, Nexus time zone (`Nexus::with_time_zone`, in the Nexus
   dates and times row) and Account mail language and product name. Workarounds
   for alpha.2 defects that the changelog's "Fixes from alpha.2 dogfooding"
   lists, such as raw SQL to filter on `is_admin`, can then go.
7. **Verify** with the production feature set: `cargo build`, `cargo test`
   and `cargo clippy --all-targets -- -D warnings`; `db:migrate` against a
   restored copy of the production database; then sign-in, "Sign out
   everywhere", Nexus access for an `is_admin` account, each configured
   provider and the health probes on staging before production.

## Why the candidate uses a new major

Adding optional privacy APIs, a new crate or more features does not by itself
require a major version. A fully compatible increment would belong in a minor
release under the [compatibility policy](compatibility-policy.md).

The current candidate does change a supported CLI/configuration contract:
13.0 removes commands and public items that 12.x applications can use:
`cargo rullst make:omni` and `cargo rullst omni`, the `offline-sync` feature
with `rullst::offline_sync`, and the `Commands::MakeOmni`/`Commands::Omni`
variants and `OmniPlatformChoice` of the `cargo-rullst` library. This
intentional change supports retaining v13 for the synchronized release train;
it does not mean every application's Rust code needs rewriting. The Omni row
above documents the replacement.

A green version-aware SemVer job alone cannot establish that this candidate
could be renamed to 12.2. The current command derives the release type from the
manifest; the 12.1-to-13 comparison permits major changes. The hosted comparison
at `4773171a` reported **0 executed checks and 254 skipped checks** for compared
libraries. Treat that as no Rust API compatibility result, not as proof that
breaking changes are absent. Any reconsideration as a minor release requires
an explicit minor-level API comparison plus review and regression tests for
CLI, configuration, serialized contracts and generated consumers. Resolve the
known Android compatibility change before making that claim.

## Use the target-major CLI

A v12 CLI cannot learn v13 migration rules just by downloading another binary.
After an admitted stable v13 exists, inspect its exact release with the v12
updater's explicit `--allow-major` option, review/install its authenticated CLI,
then start a **new invocation of that v13 CLI** for the project migration.
Pre-release discovery also requires an exact `--to` and `--prerelease`.

To evaluate the published prerelease, install its CLI from crates.io. Cargo
never selects a prerelease on its own (`cargo install cargo-rullst` installs
the end-of-life 12.x CLI), so name the exact version:

```bash
cargo install cargo-rullst --version =13.0.0-alpha.4 --locked
rullst --version
```

The output must identify `13.0.0-alpha.4`. The projects it generates pin the
framework packages with `=13.0.0-alpha.4`, as described at the top of this
guide. Reinstall with `--force` to go back to 12.x (`--version '^12'`) or to
move to a later prerelease.

To evaluate unreleased `main` changes instead, build the CLI from the reviewed
checkout:

```bash
cargo build --locked -p cargo-rullst
./target/debug/rullst --version
```

Use that explicit executable path instead of assuming a `rullst` already on
`PATH` is the same binary. This is a local source build, not authenticated
published distribution evidence. Generated projects then refer to the matching
local framework packages; keep that checkout available and review those paths.
The final package rehearsal must independently prove registry-based consumers.

## Prepare, verify, review and apply

Keep a restorable application and database backup. Quiesce writers during file
application/recovery and review the application's ignored files, toolchain and
Cargo configuration. The Git working directory's tracked and non-ignored files
are copied into private preparation storage; the root `Cargo.lock` is included
even if ignored. Typical ignored secret files and build outputs are excluded.

Using the selected v13 executable, the structured sequence is:

```text
rullst update project prepare --project /path/to/app --to 13.0.0-alpha.2 --json
rullst update project verify --prepared PREPARED_DIRECTORY --dry-run --json
rullst update project verify --prepared PREPARED_DIRECTORY --allow-project-code --json
rullst update project review --verified VERIFIED_DIRECTORY --json
rullst update project apply --verified VERIFIED_DIRECTORY --approved-review REVIEW_SHA256 --json
```

Use the directories returned by the preceding commands. Inspect the complete
review before supplying its digest. Verification executes trusted build scripts,
procedural macros and tests, and is offline by default; the private copy is not
a sandbox. Supply `--allow-network` only after reviewing that separate need.
Select the application's actual feature policy (`--features`, `--all-features`
or `--no-default-features`) instead of assuming default features cover production.

Preparation accepts supported versioned dependency declarations and preserves
their TOML structure. Unversioned path/git dependencies, ambiguous ranges,
unsupported source majors, stale inputs and unresolved source findings require
manual review. Verification requires every managed framework package in the
candidate lockfile to resolve to the selected exact target. It runs locked
workspace checks and tests before review can authorize manifest/lockfile edits.

After application, source-file recovery uses the same reviewed operation:

```text
rullst update project recover --verified VERIFIED_DIRECTORY --approved-review REVIEW_SHA256 --json
```

Recovery rejects later conflicting edits. It restores the recorded manifest and
lockfile states; it cannot undo database writes, network calls, provider effects
or other external effects of application tests. It does not deploy either state.

## Privacy remains an application decision

The preview [privacy guide](privacy-age-assurance-roadmap.md) documents the explicit local source
selection and authenticated SaaS installation contracts. Do not enable an
age restriction merely because the framework offers one. Select a server-owned
policy for the actual action and accept declarations only where that policy
permits their assurance level. Production rejects unsupported stronger methods
and process-local replay storage.

Consent-store files, replay databases, encryption/signing keys, subject/tenant
binding and retention/restore procedures need their own deployment plan.
Shared-local SQLite consent is not a multi-host consensus store; the optional
`consent-postgres` store shares consent through one authoritative PostgreSQL
database. The profile
export remains available independently of optional-consent configuration, but it
only exports the authenticated account fields supported by its adapter.

## Evidence and remaining acceptance

`update_project_cli` exercises distinct 12.1.0 and 13 packages through real Cargo
resolution, prepare/verify/review/apply/recover, changed inputs and wrong approval
digests. Those intentionally tiny packages prove the updater protocol, not the
framework's runtime API compatibility. The separate generated SaaS/LMS suites
compile actual framework source and execute application/authentication tests;
the age/privacy suites also exercise both opt-in installation orders.

Final release admission still requires the combined exact-commit workspace and
feature/consumer matrix, strict Clippy and formatting, package/native artifact
rehearsals, the required security/fuzz workflows, and this inventory updated for
all admitted changes. Application sandbox/provider journeys and deployment smoke
tests remain distinct from framework CI. See the [SST](spec.md#-12-assisted-framework-upgrade-contract)
and [delivery plan](v13-delivery-plan.md).
