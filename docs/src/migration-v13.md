# Preparing an application for v13

**The current source is `13.0.0-alpha.1`, not a published stable v13 release.**
Stable v12.1.1 maintenance lives on `v12`; `main` develops v13. The development packages use the same v13
version and internal requirements. `rullst-privacy`, `rullst-supervision` and
`rullst-media` join the candidate package inventory. Privacy has explicit
`privacy-*` umbrella features; Supervision and Media remain standalone opt-ins.
Ownership, packaged-consumer acceptance and publication remain prerequisites for
registry use. Do not request v13 artifacts from
the stable updater before those artifacts have actually been published.

This inventory covers the development source through the native age and
optional-consent consumers, plan-gated billing reports and the Android artifact-verification candidate. Revisit it as the remaining
[delivery priorities](v13-delivery-plan.md) land. It does not promise that every
existing application, provider account or deployment works without review.

## Changes from the published 12.1.0 source

| Area | Application impact |
| :--- | :--- |
| Existing runtime APIs | Source preparation changes supported dependency requirements; it invents no Rust rewrites. Review the explicit account-session schema migration below even when existing Rust calls still compile. |
| Account/session registry | Before serving requests with the new Auth recovery store, explicitly run `SqlRecoveryStore::migrate()` to add session details and the expiry index. Existing opaque sessions remain valid with unknown historical metadata. Configure expired-session maintenance and authorize new inventory/logout routes; see [session management](session-management.md). The CLI manifest updater does not apply this SQL migration. |
| Private object storage | The optional `storage-s3` candidate requires explicit signing credentials and production validation. Existing cloud constructors stay unconfigured; no bucket, IAM policy or credentials are inferred. See [private storage](private-object-storage.md). |
| R2 public URLs | `Storage::r2(...).url(key)` (and `TenantStorage::url` over R2) now returns `StorageError::Unsupported` instead of `https://<account>.r2.cloudflarestorage.com/<bucket>/<key>`. That S3 API endpoint requires a signature for every request, so the URL never loaded in a browser. Build public URLs from your `r2.dev` or custom domain in the application, or use a signed download with `storage-s3`. |
| Recoverable Live UI | Existing `LiveComponent` and `make:live` output keep their original protocol. Opt in to `live::recovery` with explicit authenticated scope, periodic authorization, persistent revisions and atomic domain updates; mount its separate browser module. Full snapshots replace child DOM and never replay uncertain actions. See [Live recovery](live-recovery.md). |
| Distributed tracing | Opt in to `telemetry::distributed` with approved operation names, upstream trust, a collector and owned flush/shutdown. The legacy initializer now uses compatible threaded OTLP/HTTP export and defaults to `127.0.0.1:4318/v1/traces`; `OTEL_EXPORTER_OTLP_ENDPOINT` is a base URL, while `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is exact. Redirects and request bodies over 1 MiB are unsupported; the legacy initializer exports at most 64 spans per request (unless `OTEL_BSP_MAX_EXPORT_BATCH_SIZE` is set), honours `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY` and reports dropped batches on stderr, while the minimized profile ignores proxy variables. Review existing collector environment configuration; [the tracing guide](distributed-tracing.md) distinguishes both metadata policies. |
| Core queue | SQLite claims jobs in due-time order, so a due scheduled or handed-back job no longer waits behind later immediate jobs, and `retry_failed_job` keeps the attempt counter (it fences claims) instead of resetting it to 0. A job no worker has a handler for is failed with `HandlerNotFound` at its 720th claim attempt instead of being handed back forever. `dispatch`/`dispatch_at` reject empty names and names over 256 bytes, and `Worker::run` rejects `job_timeout(Duration::ZERO)`, all with `QueueError::InvalidConfiguration`. Redis queue commands wait up to 10 s for a reply instead of 500 ms. Stalled recovery of a claim made without a lease (SQLite `pop`) may now happen up to two seconds after `stalled_after`, never before. |
| Core scheduler, cache and realtime | `Scheduler::start` returns the new `SchedulerError::InvalidConfiguration` for a zero task timeout; exhaustive matches in other crates are unaffected because the enum is `#[non_exhaustive]`. The Redis cache treats a zero TTL as an already-expired value (the key is removed) and a TTL beyond Redis's expiry range as no expiry, as the memory driver does. `PresenceTracker` counts connections: call `user_left` once per `user_joined`, since a user stays online until the last leave. `Channel::new` clamps the capacity to 65,536. The Traffic Shield database probe gives up at `max_db_latency` and records at least that latency. A Live recovery session no longer counts its own callback and send time as peer silence. |
| Core memory cache sweeps | `Cache::memory()` sweeps expired entries after a number of operations equal to a quarter of the entries the previous sweep kept (at least 256), instead of every 256 operations, so the sweep cost per request no longer grows with the cache. Reads still never return an expired value; unread expired entries may stay in memory longer in a large cache. |
| Studio queue monitor | Studio lists queue records with the new `QueueDriver::list_job_previews` (at most 2 KiB of each payload and error) instead of `list_all_jobs`. Custom drivers keep working through the default projection of `list_all_jobs`; override `list_job_previews` to cut values in the store. |
| Studio API playground | `Studio::with_openapi` now takes a utoipa 6 `OpenApi` (Swagger UI 10). Applications that build their document with utoipa 5 must upgrade to utoipa 6 (and `utoipa-axum` 0.3 when they use its router helpers). |
| LMS blueprint | `--blueprint lms` now generates a small starter: catalog, modules, lessons, an accessible player, enrollment, owner-bound progress, login and a Nexus admin, with hot reload. The complete Academy scaffold (schools, roles, quizzes, activities, scores, automation, notifications, publication, privacy lifecycle) and `--lms-modules` were removed; existing generated applications keep their code. Registration no longer generates the school-membership hook, and the learner dashboard no longer claims a default demo school: it points to the course catalog. |
| Consumer generators | `make:supervision` was removed with the complete Academy LMS it targeted; integrate `rullst-supervision` directly. `make:privacy` and `make:age-gate` now target only the SaaS starter (`--blueprint saas`, which requires `--tenant-ref`). |
| `html!` event handlers | A dynamic value in an `on*`, `hx-on` or `hx-on-*` attribute (for example `onclick={handler}`) no longer compiles, because escaping cannot make data safe inside JavaScript. Static handler strings still compile; move data-driven handlers into a nonce'd script with `addEventListener` and pass values through `data-*` attributes. The default CSP already blocked such inline handlers. |
| Core request validation | `ValidatedForm`/`ValidatedJson` return 413 for oversized bodies and 415 for a wrong content type (HTMX requests receive the same code in `X-Rullst-Validation-Status`); other read failures stay 400. Nested errors are keyed `address.zip` and `items[0].name`, and `ValidationError` formatting no longer includes submitted values. Update clients or tests that expected 400 for these cases. |
| Core feature flags and scheduler | A user outside a declared A/B split now resolves to `"disabled"` instead of falling through to the next driver, and a negative database `rollout_percentage` means 0%. `Scheduler::task` uses POSIX weekday numbering (0 and 7 are Sunday) with the day-of-month OR day-of-week rule in UTC; review numeric weekdays in existing schedules. `RullstConfig::environment()` now reports the environment the Server enforces, including a value read from `.env`. |
| Memory feature-flag splits | A `MemoryFeatureDriver::override_variants` flag (including `FeatureManager::overrides()`) no longer reports `enabled`/`enabled_for` as true for everyone. Like the Env, TOML and DB drivers, `enabled_for` is true only for identifiers assigned a variant named `"enabled"`; like the Env and TOML drivers, `enabled` is false. Gate A/B code on `variant`. |
| Security headers | Core and both Security header layers preserve an endpoint's exact `Referrer-Policy: no-referrer`, including when it occurs among duplicate values. Other endpoint values still yield to the configured baseline. Review handlers that intentionally set this more restrictive policy. |
| Core CSRF on HEAD | `csrf_middleware` handles `HEAD` like `GET`: it installs the request-scoped `CsrfToken` and, when the request carries no CSRF cookie, sends the same `Set-Cookie` that GET would. A `get` route that extracts `Extension<CsrfToken>` now answers HEAD (monitors, crawlers, `curl -I`) with its GET status instead of 500. |
| Hot-reload machine endpoints | `Server::new_hot(...).with_machine_endpoints(policy)` now authenticates the policy's exact routes in the development hot-reload server, as the static server already did in every environment. Previously hot reload ignored the policy and those routes ran unauthenticated; development machine clients must now send the configured credentials. |
| Core JSON PII masking | With `enable_pii_masking`, JSON string escapes are decoded before masking, so `\uXXXX` hex digits never join a card-number run (which produced invalid JSON such as `\u****`), while escaped digits and `@` are masked like their literal characters. A masked character is written as a literal `*`; unmasked escapes keep their original spelling. |
| Android release command | `omni android --release` now requires the expected public DER certificate and trusted SDK `apksigner.jar` path, and rejects missing, unchanged, ambiguous or incorrectly signed output. Configure `RULLST_ANDROID_SIGNING_CERTIFICATE` / `RULLST_ANDROID_APKSIGNER_JAR` or the corresponding CLI options. See the [signing guide](tutorials/49-omni-android-signing.md). The old Rust helper signature remains; its environment contract is stricter. |
| Age assurance | Optional `rullst-privacy` APIs and `make:age-gate` add an authenticated native declaration journey. Existing apps acquire no age policy, verified age, guardian relationship, replay storage or camera capture by upgrading a dependency. |
| Optional consent and export | `make:privacy` adds explicit versioned choices, effective withdrawal of the demonstrated optional greeting and an authenticated own-account name/email export. It requires reviewed application installation and explicit consent-store initialization. It is not a complete export of all application data or automatic worldwide legal compliance. |
| Project context | New projects receive application instructions and a bounded metadata map. `generate:ai-context` replaces recognized legacy source-concatenation output, preserves existing `AGENTS.md`, and adds a non-writing `--check`. See the [context guide](project-context.md) for size/path/configuration limits. |
| Typed API generation | `generate:api` is an explicit additive OpenAPI profile with generated Rust codecs and a TypeScript client. Install/review the schema and application handlers; existing scanning generators and routes are not migrated automatically. See the [supported profile](typed-api.md). |
| CLI generator output | `make:migration:auto` reads `#[orm(table_name = "...")]`, qualified `#[derive(rullst_orm::Orm)]` and a `table` option written after other `#[orm(...)]` options, so it diffs the declared table instead of a guessed `<struct>s` table. `make:live` imports `rullst::async_trait` instead of the undeclared `async_trait` crate; edit components generated earlier the same way. `make:scalar` imports `rullst::web::axum::Router` instead of the undeclared `axum` crate. `eject` writes a template that compiles (Axum through `rullst::web::axum`) and wraps its placeholder routes in the configured security baseline; it still does not carry over application routes, so `--force` output needs the routes moved from `src/main.rs.rullst-backup`. `foundry:deploy` uploads the binary to `/opt/rullst/<app>/incoming/<bin>.upload` (created `0700` for the SSH user during provisioning) instead of `/tmp`, and the remote step requires `stat` and `sha256sum` to check its owner and digest. `foundry:init` creates a missing `.gitignore`, no longer treats a comment or `!Foundry.toml` as protection, and writes `Foundry.toml` with mode `0600`. `make:model` rejects names such as `Match` or `Type` whose module would be a Rust keyword, as `make:resource` already did. `make:migration` keeps leading `m` characters of the name (`modify_users` previously became `odify_users`) and rejects names that are not ASCII letters, digits, `_` or `-`; generators that refresh `src/migrations/mod.rs` now fail on an `m*.rs` file whose name is not a valid module name instead of writing an unparsable registry. `make:controller --api` and `make:resource --api` handlers extract `Json<CreateDto>`/`Json<UpdateDto>` instead of `Form`, so clients must send `application/json`; controllers generated earlier keep `Form` until edited. `generate:ts` also scans `src/lib.rs` and turns `{id}`/`{*path}` captures into URL-encoded method arguments; regenerate `rullst-client.ts`, whose parameterized methods change signature. Re-run `hook:install` to refresh a managed `commit-msg` hook: it now accepts Git's merge, revert and `fixup!`/`squash!`/`amend!` subjects. `generate:openapi` takes an operation summary only from the handler with the exact name, not from an earlier function whose name starts with it (`show_archived` for `show`). `make:worker` handlers no longer print the full job payload; existing workers keep their logging until edited. Fixture-mode `make:billing` (and SaaS starter) checkout/portal handlers answer a database failure with a generic `Billing identity is unavailable` 500 and log the error server-side. `make:migration:auto` ignores the ORM `migrations` table and `rullst_*` tables, and prints destructive-only differences instead of writing and registering a comment-only `auto_sync` migration on every run. `hook:install` fails when `core.hooksPath` selects another directory, instead of reporting success for wrappers Git never runs. `inspect schema` prints the ORM model schema derived from `#[derive(Orm)]` structs when no project-provided `rullst-schema.json` exists, instead of asking for a file that nothing generates. |
| ORM partial updates | `update_partial()` now merges into a freshly loaded row and runs full-save policy/hooks/audit/post-commit behavior. It performs full-row SQL and refreshes the caller object; review audit identity, triggers, unsaved local fields and outer rollback. New `save_with_tx` is explicit. See [the migration contract](transactional-partial-updates.md). |
| ORM derive checks | Some models that compiled on 12.x now fail at compile time instead of misbehaving at runtime: `belongs_to` without `foreign_key` defaults to `<related model>_id` (it previously used `<this model>_id`, joining on the wrong column); `local_key` on `belongs_to`/`morph_to` and `related_key` on `has_one`/`has_many`/`morph_one`/`morph_many` are rejected because those relations ignore them; and `searchable` models need a lowercase, Scout-valid table name. Add an explicit `foreign_key`, remove the ignored option or set `#[orm(table = "...")]`. |
| ORM queries and cache | `count()`/`paginate()` totals count DISTINCT rows and GROUP BY groups; offset `chunk()` pages are ordered by primary key unless `order_by` is set; `SecretString` columns are rejected in filters, ordering, grouping and `pluck_*`. While a transactional `stream()` is open, other ORM calls on that transaction return `Validation` instead of waiting. Models without a `tenant_column` share one global query-cache partition, so cache keys built manually with `query_cache::query_key` inside `with_tenant` for such models no longer match generated keys. Scout-backed `search()` results follow the engine's ranking unless `order_by` is set. Generated writes now bind `#[sqlx(json)]` fields as SQLx `Json` (JSON on PostgreSQL/MySQL instead of the field's own SQL type), so such a field type needs `Serialize`; a type that implemented only `Encode` no longer compiles. |
| ORM query-cache index | Generated `.remember(...)` keys move to the `rullst:orm:cache:v4:` prefix, and each table index becomes a Redis sorted set (`<prefix>:index`) scored by entry expiry instead of the `<prefix>:keys` set. Entries written under the previous prefix are not read again and expire through their TTL, so caches start cold after the upgrade; during a rolling upgrade a write on an instance of the other version does not invalidate the new entries before their TTL. Index members of expired entries are pruned on each cache write and no longer count toward the 10,000-key `PostCommit` invalidation cap. Tools that inspected the old `:keys` set must read the sorted set. |
| Turso migrations | `TursoStore::rollback_last` and `TursoOrm::rollback_last` now refuse, with the same drift error as `migrate`, a latest migration whose digest (its up and down statements) differs from the recorded one, instead of running the changed down statements and deleting the history row. Restore the applied definition to roll it back. |
| Schema table names on PostgreSQL | `Schema::create` and `Schema::drop_if_exists` lower-case the quoted table name on PostgreSQL, matching the unquoted names generated model SQL uses, so `Schema::create("UserProfiles", ...)` now creates `userprofiles`. A table an earlier version created as `"UserProfiles"` is not dropped by `drop_if_exists("UserProfiles")` and stays unreachable by generated SQL; rename it with `ALTER TABLE "UserProfiles" RENAME TO userprofiles`. MySQL/MariaDB and SQLite are unchanged. |
| Legacy `SecretString` ciphertext | Pre-v12 `SecretString` values, which carry no key ID, now decrypt with the current key and then each `RULLST_ENCRYPTION_KEYRING` key (`default` first), so they stay readable after a documented rotation. When the current key does not match, a malformed keyring now fails the read with `PrivacyError::EnvError` instead of `DecryptionFailed`. |
| `SecretString` client input | `SecretString`'s `Deserialize` still decrypts any serde envelope under the configured key or keyring, and that envelope binds no model, field or owner. Review request types that deserialize a `SecretString` from client input, including models used directly as JSON bodies, and add `#[serde(deserialize_with = "rullst_orm::privacy::deserialize_plaintext_secret")]` (or `deserialize_optional_plaintext_secret`, unpublished v13 API), which rejects envelope-shaped values without decrypting them. |
| Offline Redis mock | The offline `RedisDataStore` mock returns equal `sorted_set_top` scores in descending lexicographic member order, like Redis `ZREVRANGE`, instead of ascending order. Update tests that relied on the old tie order. |
| SQLite DSN paths | The missing-file preparation before connecting percent-decodes the SQLite DSN path as SQLx does, so `sqlite://data%20dir/app.db` creates `data dir/app.db`, the file SQLx opens, instead of a stray `data%20dir/app.db`. Stray encoded-name files left by earlier versions can be removed. |
| Auto-healing diagnostics | `SchemaErrorInterceptor::diagnose_sql_error` returns `None` for constraint violations, `already exists` errors, other messages that merely mention a relation, and names that are not plain identifiers. Missing-table suggestions use SQLite or MySQL DDL when the message comes from those drivers, and SQLite `no such column` and MySQL `Unknown column`/`Table ... doesn't exist` messages are recognized. |
| ORM migrations | The `Migration` trait gains `within_transaction()` (default `false`, unpublished v13 API). Returning `true` makes the runner apply `up()`/`down()` and its `migrations` record in one `Orm::transaction`; only statements that join it (`Schema`, `execute_query!`, generated model methods) are covered, and MySQL/MariaDB DDL still commits implicitly. The template written by the ORM artisan `make:migration` now opts in, so such a migration that sends queries to `Orm::pool()` directly must return `false`. Existing migrations keep the separate statements. |
| ORM instance mutations | `save()` of a row deleted after it was loaded, and `delete()`/`force_delete()` of a missing row, now fail with `RecordNotFound` (tenant models keep their tenant-scope `Validation` error) instead of returning `Ok` and running observers, audit and post-commit effects. A second soft `delete()` of a trashed row fails the same way instead of re-stamping its deletion time, and `restore()` of a missing or live row is a no-op on every model. `cascade_soft_delete` now also trashes children that the child model's `global_scope` hides. A model whose only persisted field is `id` can now be inserted. An auditable `save()` locks the row it diffs (`FOR UPDATE` on PostgreSQL/MySQL), `deleted`/`force_deleted`/`restored` audit entries record the persisted row instead of the in-memory handle, and that read, revision restores, `restore()` re-reads and `belongs_to_many` pivot loads now fail with the configured query timeout instead of waiting indefinitely. Callers that deleted idempotently must accept `RecordNotFound`. |
| ORM sandbox tests | `#[rullst_orm::test]` keeps the function's declared return type and returns the body's value after the rollback, so a test returning `Err` now fails instead of passing. A test whose declared type does not match its body, or is not a `Termination` type such as `Result<(), E: Debug>`, no longer compiles; fix the signature. Post-commit effects of sandboxed writes (`committed` observers, cache invalidation, Redis events, Scout) no longer run, because the sandbox never commits; assert them in a test that commits through `Orm::transaction`. |
| ORM model SQLx options | A struct-level `#[sqlx(...)]` option other than `default` on a `#[derive(Orm)]` model, such as `rename_all = "camelCase"`, no longer compiles: `FromRow` decoded the renamed columns while generated SQL used the field names, so writes or reads failed at runtime. Name the fields after their columns instead. |
| ORM trashed scopes | `only_trashed()` on a model without soft deletes now fails with `Validation` instead of returning, counting or bulk-deleting every live row as if it were trashed (an "empty trash" `only_trashed().delete_all()` deleted the whole table). Remove the call, or give the model a `deleted_at` field or `#[orm(soft_delete)]`. |
| ORM bulk soft deletes | On soft-delete models, `delete_all()` with `with_trashed()` or `only_trashed()` now fails with `Validation` instead of re-stamping the deletion time of rows that were already trashed, which kept age-based purges from ever seeing them expire. Bulk-delete live rows without these modifiers and purge trashed rows with `force_delete()`. |
| ORM joined scopes | Generated tenant and soft-delete predicates and the `chunk_by_id` keyset are now qualified with the model's table (`orders.tenant_id = ?`, `orders.deleted_at IS NULL`, `ORDER BY orders.id ASC`), so a lazy `belongs_to_many` load or a join with a table that has the same columns no longer fails with an ambiguous column. Update tests that compare generated SQL text; Redis query-cache entries are keyed by the new SQL and are rebuilt on the next read. |
| ORM chunk bounds | `chunk()`, `chunk_with_tx()`, `chunk_by_id()` and `chunk_by_id_with_tx()` now honour an explicit `limit(n)` as a cap on the total rows handed to the handler and an explicit `offset(k)` as the starting point, instead of silently walking every matching row from the first one. Remove `limit()`/`offset()` from chunked queries that relied on them being ignored. |
| ORM eager pivot order | An eager `belongs_to_many` load now orders each parent's related rows like the related query, so an `order_by` in `with_<relation>_constrained` applies, instead of following the order of the unordered pivot rows. Without an `order_by` the order remains unspecified. |
| PersonalData reports | `compliance_schema()` now reports the table `#[derive(Orm)]` uses (`#[orm(table)]` or the `<struct>s` default, previously the lowercased struct name) and lists in `encrypted_fields`/`has_encrypted_data` only `#[orm(encrypted)]` and `SecretString` columns; `#[privacy]` fields, which are not encrypted by the derive, are listed by the new `ComplianceModel::personal_fields()`. |
| Nexus derive | A field annotated `#[nexus(primary_key)]` is now the record key even when a later field is named `id` (previously the last of them won, and both were hidden and read-only). Two annotated fields, or an annotation that contradicts the struct-level `#[nexus(primary_key = "...")]`, no longer compile; keep one key declaration. A non-integer derived key (a UUID or code) is now listed and entered in the create form instead of being hidden and read-only; mark it `#[nexus(readonly)]` or `#[nexus(hidden)]` to keep the previous behaviour for a database-generated key. Fields typed `chrono::DateTime<Utc>`, `DateTime<chrono::Utc>` or `NaiveDateTime` now get the validated date-time widget instead of free text. |
| Nexus credentials | `NexusAuthPolicy::basic_from_env` (and release builds of `local_development_or_basic_from_env`) reads `NEXUS_ADMIN_USERNAME`/`NEXUS_ADMIN_PASSWORD` from the process environment, then `.env` in the working directory only, through `rullst::config::project_setting`. It no longer loads `.env` (or a parent directory's `.env`) into the process environment, so code that relied on that side effect must read its own settings; a malformed or unreadable `.env` now fails with the new `NexusBuildError::InvalidDotenv` instead of being ignored. |
| CLI migration catalog | `rullst-upgrade-rules-v3` recognizes source majors 12 and 13. v5/v6 applications, including their v11-era ecosystem crates, first upgrade to v12 with the v12 CLI; the v13 CLI no longer carries their rules. The installed CLI must belong to the exact target major. Preparations from the earlier catalog must be prepared and verified again. Downgrades still fail. |
| CLI generators | `make:model --migration` and `make:resource` skip the create-table migration when the model file or a `*_create_<table>.rs`/`*_create_<table>_table.rs` migration already exists, because its rollback would drop the live table; add schema changes with `make:migration`. `generate:models`/`make:models-from-db` refuse to replace an existing `<table>.rs` and append missing declarations to an existing `mod.rs` instead of rewriting it; move colliding files aside or use another `--output`. `make:k8s`, `dockerize`, `nixify` and `generate:buildah` no longer replace existing manifests, `Dockerfile`, `flake.nix`, `.envrc` or `build_buildah.sh`; move a file aside to regenerate it. `cargo rullst auth` rejects Turso-primary projects, refuses to replace existing user/auth files or to add a second users-table migration, enables the `orm` and `auth` features and registers its modules in the crate root. `make:mfa` now generates a server-side factor store (`user_mfa_factors` migration, replay-protected verification bound to the authenticated `Extension<i32>` user id) instead of a handler that verified a client-supplied secret; it enables `orm` and `security`, rejects Turso-primary projects and refuses to overwrite. Replace a previously generated `mfa.rs` that accepted a `secret` form field. |
| CLI operations | `deploy --platform fly` and `--platform railway` now exit non-zero when the installed `flyctl deploy` or `railway up` fails, instead of printing a hint and exiting 0; a missing provider CLI is still advisory. Update scripts that relied on the old exit status. `update project verify` resolves the candidate with `cargo update --workspace` instead of `cargo generate-lockfile`, so unrelated `Cargo.lock` pins are kept; verifications recorded with the old command no longer pass `review`/`apply` and must be run again. Project-copy Cargo/rustc commands pin `RUSTUP_TOOLCHAIN` to the caller's toolchain (inherited value, otherwise rustup's default) and ignore the project's `rust-toolchain(.toml)`; set `RUSTUP_TOOLCHAIN` to verify with a project-pinned channel. `foundry:deploy` runs the service as a dedicated `rullst-<app>` system account (it now requires `useradd`) in a sandboxed unit instead of root; existing `/opt/rullst/<app>/data` is re-owned, and the application can write only there, so move state written elsewhere (for example an absolute SQLite path) under that directory first. |
| CLI diagnostics and side effects | `generate:diagram` writes a marker comment at the top of `diagram.md` and refuses to replace a `diagram.md` it did not generate; the refresh after `make:controller`, `make:model`, `make:middleware`, `make:worker`, `make:island`, `auth`, `make:billing`, `make:cors` and `make:jwt` keeps such a file and prints a notice. A diagram from an earlier release (a single unmarked Mermaid block) is still replaced. Move a hand-written `diagram.md` aside to regenerate it. `audit --compliance` and `audit --sbom` fail instead of writing through a symlinked `SECURITY_COMPLIANCE.md` or `sbom-cyclonedx.json`. ## Why the candidate uses a new major

Adding optional privacy APIs, a new crate or more features does not by itself
require a major version. A fully compatible increment would belong in a minor
release under the [compatibility policy](compatibility-policy.md).

The current candidate does change a supported CLI/configuration contract:
in 12.1, the Android release command and `build_android_release()` accept the
four signing variables without requiring the two verification paths. The new
implementation rejects that invocation until the expected public certificate
and trusted verifier are supplied. Keeping the Rust function signature does
not preserve that behavior. This intentional change supports retaining v13
for the synchronized release train; it does not mean every application's Rust
code needs rewriting. The signing guide above documents the required setup.

A green version-aware SemVer job alone cannot establish that this candidate
could be renamed to 12.2. The current command derives the release type from the
manifest; the 12.1-to-13 comparison permits major changes. The hosted comparison
at `4773171a` reported **0 executed checks and 254 skipped checks** for compared
libraries. Treat that as no Rust API compatibility result, not as proof that
breaking changes are absent. Any reconsideration as a minor release requires
an explicit minor-level API comparison plus review and regression tests for
CLI, configuration, serialized contracts and generated consumers. Resolve the
known Android compatibility change before making that claim.

## Use the target-major CLI

A v12 CLI cannot learn v13 migration rules just by downloading another binary.
After an admitted stable v13 exists, inspect its exact release with the v12
updater's explicit `--allow-major` option, review/install its authenticated CLI,
then start a **new invocation of that v13 CLI** for the project migration.
Pre-release discovery also requires an exact `--to` and `--prerelease`.

For a source evaluation today, build the CLI from the reviewed v13 checkout:

```bash
cargo build --locked -p cargo-rullst
./target/debug/rullst --version
```

The output must identify `13.0.0-alpha.1`. Use that explicit executable path
instead of assuming a `rullst` already on `PATH` is the same binary. This is a
local source build, not authenticated published distribution evidence. Generated
pre-release projects may refer to matching local framework packages; keep that
checkout available and review those paths. The final package rehearsal must
independently prove registry-based consumers.

## Prepare, verify, review and apply

Keep a restorable application and database backup. Quiesce writers during file
application/recovery and review the application's ignored files, toolchain and
Cargo configuration. The Git working directory's tracked and non-ignored files
are copied into private preparation storage; the root `Cargo.lock` is included
even if ignored. Typical ignored secret files and build outputs are excluded.

Using the selected v13 executable, the structured sequence is:

```text
rullst update project prepare --project /path/to/app --to 13.0.0-alpha.1 --json
rullst update project verify --prepared PREPARED_DIRECTORY --dry-run --json
rullst update project verify --prepared PREPARED_DIRECTORY --allow-project-code --json
rullst update project review --verified VERIFIED_DIRECTORY --json
rullst update project apply --verified VERIFIED_DIRECTORY --approved-review REVIEW_SHA256 --json
```

Use the directories returned by the preceding commands. Inspect the complete
review before supplying its digest. Verification executes trusted build scripts,
procedural macros and tests, and is offline by default; the private copy is not
a sandbox. Supply `--allow-network` only after reviewing that separate need.
Select the application's actual feature policy (`--features`, `--all-features`
or `--no-default-features`) instead of assuming default features cover production.

Preparation accepts supported versioned dependency declarations and preserves
their TOML structure. Unversioned path/git dependencies, ambiguous ranges,
unsupported source majors, stale inputs and unresolved source findings require
manual review. Verification requires every managed framework package in the
candidate lockfile to resolve to the selected exact target. It runs locked
workspace checks and tests before review can authorize manifest/lockfile edits.

After application, source-file recovery uses the same reviewed operation:

```text
rullst update project recover --verified VERIFIED_DIRECTORY --approved-review REVIEW_SHA256 --json
```

Recovery rejects later conflicting edits. It restores the recorded manifest and
lockfile states; it cannot undo database writes, network calls, provider effects
or other external effects of application tests. It does not deploy either state.

## Privacy remains an application decision

The preview [privacy guide](privacy-age-assurance-roadmap.md) documents the explicit local source
selection and authenticated SaaS/LMS installation contracts. Do not enable an
age restriction merely because the framework offers one. Select a server-owned
policy for the actual action and accept declarations only where that policy
permits their assurance level. Production rejects unsupported stronger methods
and process-local replay storage.

Consent-store files, replay databases, encryption/signing keys, subject/tenant
binding and retention/restore procedures need their own deployment plan.
Shared-local SQLite consent is not a multi-host consensus store. The profile
export remains available independently of optional-consent configuration, but it
only exports the authenticated account fields supported by its adapter.

## Evidence and remaining acceptance

`update_project_cli` exercises distinct 12.1.0 and 13 packages through real Cargo
resolution, prepare/verify/review/apply/recover, changed inputs and wrong approval
digests. Those intentionally tiny packages prove the updater protocol, not the
framework's runtime API compatibility. The separate generated SaaS/LMS suites
compile actual framework source and execute application/authentication tests;
the age/privacy suites also exercise both opt-in installation orders.

Final release admission still requires the combined exact-commit workspace and
feature/consumer matrix, strict Clippy and formatting, package/native artifact
rehearsals, the required security/fuzz workflows, and this inventory updated for
all admitted changes. Application sandbox/provider journeys and deployment smoke
tests remain distinct from framework CI. See the [SST](spec.md#-12-assisted-framework-upgrade-contract)
and [delivery plan](v13-delivery-plan.md).
