# Rullst Studio 📊

`rullst-studio` is the built-in, local-first administration and monitoring dashboard for the Rullst Framework. It provides an immediate visual interface to inspect your database, background workers, and real-time application metrics without needing third-party SaaS tools.

## ✨ Features

- **Database GUI:** View, edit, insert, and delete records across all your tables via an elegant Web UI.
- **Worker Queue Monitoring:** Track the status of Redis or Postgres-backed background jobs. View failed jobs and retries in real-time.
- **Live Tracing & Logs:** Connects seamlessly to the OpenTelemetry spans generated by `rullst-core` to visualize request latency and error bottlenecks.
- **Local-First Security:** Rullst Studio binds exclusively to `localhost` by default. Production access requires strict Authentication middleware.

## 🚀 Quickstart

Add `rullst-studio` to your project:

```bash
cargo add rullst-studio
```

### Launching the Studio

You can embed Rullst Studio directly into your existing Axum/Rullst router, or launch it via the CLI.

**Embedded Integration:**

```rust
use rullst::{Router, Server};
use rullst_studio::StudioLayer;
use rullst_orm::Orm;

#[tokio::main]
async fn main() {
    let pool = Orm::pool();
    
    // Attach the Studio Layer to a specific path
    let app = Router::new()
        .nest("/_studio", StudioLayer::new(pool).into_router());

    Server::new().route("/", app).run().await;
}
```

Now, navigate to `http://localhost:3000/_studio` to see your live database dashboard.

**CLI Launch:**

If you don't want to embed it, you can launch it statelessly via the Rullst CLI:

```bash
cargo rullst studio
```

## 🔐 Security Audit

`rullst-studio` is designed strictly for local development and secure-intranet deployments. When mounted in production, it is highly recommended to wrap the `StudioLayer` in a `rullst-auth` Role-Based Access Control (RBAC) middleware ensuring only Admins can access the dashboard.
